## 第一问：已知数据下的确定性优化

核心方法是确定性混合整数线性规划（MILP）。

- 将附件中的时刻值视为瞬时功率，相邻端点取平均，得到每个10分钟区间的平均功率，再乘 \(1/6\) 转为区间电量。
- 以全天普通购电费用最小为目标。
- 决策变量包括普通购电、充电、放电、弃光、储能量以及充放电方向二元变量。
- 约束包括：
  - 微网能量平衡；
  - 储能 SOC 递推；
  - SOC 上下限；
  - 充放电功率限制；
  - 同一时段不能同时充放电；
  - 日初、日末储电量均为 6000 kWh。
- 使用 `scipy.optimize.milp`，底层为 HiGHS 求解器。

因此第一问本质上是一个“完全知道当天负载、光伏和电价时的最优储能套利与购电计划”。

主要说明见：[第一问 README](<question1/README.md>)、[结果说明](<question1/results/结果说明.md>)。

需要注意：README 和结果说明中的最优费用略有差异，应该来自不同的数据预处理版本；当前总 README 指向的是采用端点均值预处理的结果。

## 第二问：日前预测＋购电规划＋日内控制

第二问分成预测层、日前规划层和日内执行层。

### 1. 负载和光伏预测

负载预测比较了：

- 上周同期 Baseline；
- XGBoost；
- LightGBM；
- SARIMA。

最终负载选择 XGBoost。特征主要包括：

- 前1、2、7、14天同期滞后；
- 同时段滚动统计；
- 时段周期特征；
- 星期和周末特征；
- 年内季节周期特征。

光伏预测比较了历史同期均值、树模型、日总量分解、晴空包络和自适应加权等方法。由于没有天气预报变量，最终采用自适应加权的近期同期预测，效果略好于普通7天同期均值。

预测采用扩展窗口滚动回测：预测某一天时，只允许使用该日零点以前的数据，避免时间泄漏。

预测结果仍先给出瞬时端点，然后通过相邻端点平均转换成144个区间预测值。

预测方法见：[第二问预测 README](<question2/README.md>) 和 [预测模块交接文档](<question2/交付.md>)。

### 2. 规划方案

第二问实际比较了四个主要方案：

| 方案 | 日前购电计划 | 日内储能控制 |
|---|---|---|
| A | 点预测确定性 MILP | 贪心控制 |
| B | 点预测确定性 MILP | LP-MPC |
| C | 净负载误差分位数裕量＋MILP | LP-MPC |
| D | 两阶段场景随机 MILP | LP-MPC |

其中：

- A 是最简单基准：有缺口就尽量放电，富余就尽量充电。
- B 保持相同的日前购电方法，但每10分钟重新计算剩余时域的充放电策略，只执行当前一步，即模型预测控制 MPC。
- C 根据历史净负载预测误差的分位数给日前需求增加安全裕量。
- D 从最近历史中抽取完整一天的负载—光伏成对残差，生成8个联合场景；所有场景共享同一套日前购电合同，不同场景拥有各自的电池和紧急购电补救变量。

D 的目标是在普通购电成本与预测失误后五倍价格紧急购电之间进行权衡。最终选用的是 D，即“两阶段场景随机 MILP＋日内 LP-MPC”。

需要准确表述为“两阶段随机近似”，因为场景中的未来补救变量可以看到完整场景路径，它不是严格的多阶段随机控制。

主要说明见：[模型与执行步骤](<question2/第二问_新144段计算/support/模型与执行步骤.md>)。

## 第三问：分时光伏预报＋付费调单＋滚动随机优化

第三问在第二问的框架上增加了两个内容：

- 6:00、12:00、18:00可以获得更新的光伏预报；
- 可以付费增加或取消原普通购电订单。

整体方法仍是滚动两阶段场景随机 MILP＋MPC。

### 具体做法

- 零点先制定全天原始普通购电计划 \(g_t\)。
- 在启用的6、12、18点读取相应版本的光伏预报。
- 根据最新 SOC、最新预测和历史预测残差重新生成场景。
- 对允许调整的后续合同区间重新求解。
- 当前正式调整区间的订单必须跨场景一致；更远期订单只作为场景中的预案。
- 电池每10分钟读取当前状态并滚动优化，只执行第一步。

调单费用模型为：

- 增购电量按原价的1.5倍计费；
- 取消订单先退原费用，再收取消部分50%的违约费，净效果相当于每取消1 kWh只退回原价的50%；
- 紧急购电按普通电价的5倍计费。

对光伏预报启用时刻一共比较8种组合：

- 仅0点；
- 0、6点；
- 0、12点；
- 0、18点；
- 0、6、12点；
- 0、6、18点；
- 0、12、18点；
- 0、6、12、18点。

各方案从共同初始 SOC 开始连续运行，不能每天重置储能量。最终根据实际运行现金账本选择启用时刻组合，而不是直接比较随机模型内部的期望目标值。

主要说明见：[第三问模型与复现说明](<question3/第三问_完整计算/第三问_完整计算/notes/问题三_模型与复现说明.md>)。

## 第四问：波动电价预测＋联合场景调度

第四问可以看作把前三问的规划模型放到波动电价环境中重新计算。

### 1. 电价预测

电价采用滚动 XGBoost：

- 零点预测未来145个价格节点，再转换为144个区间价格；
- 6、12、18点重新训练并更新剩余时段电价预测；
- 特征包括时刻、星期周期、前2/3/7日同期价格、近期滚动统计和发行时已知的最新价格节点；
- 使用最近最多28个历史发行日训练；
- 未来实际价格不进入控制，只用于事后结算。

### 2. 两种价格不确定性处理

比较了两种方式：

- 点价格方案 P：所有负载/光伏场景共用同一条 XGBoost 电价预测；
- 联合价格场景 J：负载、光伏和价格使用同一个历史日的预测残差，保留三者之间的相关关系。

价格误差采用对数比例残差，因此生成的场景价格始终为正。

这里“点价格方案”仍然是负载/光伏随机规划，并不是完全确定性模型。

### 3. 规划模型

继续采用两阶段随机 MILP＋滚动 MPC：

- 零点决定原始购电合同；
- 允许的时刻决定增加量、取消量和最终订单；
- 场景中考虑充放电、弃光、未使用但已付费的普通电以及紧急购电；
- 目标为预测期望现金费用＋软末端库存惩罚；
- 当后续普通订单已经锁定时，电池控制可简化为 LP；
- 仍有未来调单机会时，需要保留 MILP，以共同考虑未来增购、退单和电池使用。

第四问分别重算：

- 4-2：普通购电计划固定，日内只更新价格和电池控制；
- 4-3：在指定光伏预报时刻允许正式调单。

候选策略只用开发窗口选定并冻结，后续测试期不再反向修改模型。还进行了场景数、历史窗口、末端库存惩罚、随机种子、初始 SOC、贪心/MPC和价格更新频率等敏感性分析。

主要说明见：[第四问模型与操作方法](<question4/第四问_完整计算/第四问_完整计算/第四问_模型与操作方法.md>) 和 [第四问结果与结论](<question4/第四问_完整计算/第四问_完整计算/第四问_结果与结论.md>)。
